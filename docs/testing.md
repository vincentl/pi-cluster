# Hardware test checklist

Run on the real cluster, top to bottom, following the Readme. Each item says where to run
it, what it should print, what counts as a pass, and roughly how long it takes. Rows marked
pi-login run in an ssh session on the head node, where `sudo` wants the password you gave `pi`
in Imager; rows marked workstation run on your own computer. Commands use
the defaults in `cluster.env` (`pi-login`, `pi-001`, `10.0.0.1`). Record the results in
`ai/test-logs/YYYY-MM-DD.md`; the template is at the end.

Before you start, note the time: the log records blank card to first compute node up.

Fan test (5.10). It prints one line at idle, loads all four cores for three minutes, then
watches the node cool for a minute, printing what the fan does. Nodes whose HAT fan always runs
have nothing to test.

```bash
ssh pi-003 'fan=$(grep -l pwmfan /sys/class/hwmon/hwmon*/name | xargs dirname)
show() { echo "$1  $(( $(cat /sys/class/thermal/thermal_zone0/temp) / 1000 )) C  pwm $(cat $fan/pwm1)  rpm $(cat $fan/fan1_input)"; }
show idle
for i in 1 2 3 4; do timeout 180 sh -c "while :; do :; done" & done
for s in $(seq 18); do sleep 10; show load; done
for s in $(seq 6); do sleep 10; show rest; done'
```

The thresholds are the Pi 5 defaults from the device tree
(https://raw.githubusercontent.com/raspberrypi/linux/rpi-6.18.y/arch/arm64/boot/dts/broadcom/bcm2712-rpi-5-b.dts,
`cooling_fan` and `thermal_trips`). The fan node is disabled there and the firmware enables it
(https://raw.githubusercontent.com/raspberrypi/linux/rpi-6.18.y/arch/arm/boot/dts/overlays/README,
`cooling_fan`). After the load stops, the fan steps down 5 °C below each threshold.

## Maintenance

| # | Where | Command | Expected | Pass if | Time |
|---|-------|---------|----------|---------|------|
| M.1 | pi-login | with the nodes running: `sudo bash pi-cluster/head/image-run.sh true` | `warning: compute nodes are running from the image: 10.0.1.1 …`, one address per running node | the warning | 1 min |
| M.2 | pi-login | unplug every node; `sudo bash pi-cluster/head/image-run.sh apt update`, then `… apt full-upgrade -y` | no running-nodes warning; apt runs to the end; `invoke-rc.d: policy-rc.d denied execution of …` lines are expected, as in 3.1 | exits 0, and no service starts | 5-15 min |
| M.3 | pi-login | `ls -l /image/pi5/boot/firmware/kernel_2712.img /image/pi5/boot/firmware/initramfs_2712; wc -c < /image/pi5/etc/machine-id`, then `sudo bash pi-cluster/head/20-netboot.sh` | new dates if M.2 upgraded the kernel; `0`; the script prints only `showmount -e` and "done" | machine ID empty, and the upgrade undid none of the image's settings | 2 min |
| M.4 | workstation | plug the nodes back in; after about 90 s, `ssh pi-001 'uname -r; uptime'`, and the same for every node | the kernel M.2 installed, if it installed one; uptime | every node boots the upgraded image | 3 min |
| M.5 | pi-login | `sudo bash pi-cluster/head/image-run.sh`, then `exit` | the running-nodes warning, then a root shell inside the image | the shell opens | 1 min |
| M.6 | pi-login | once the repo is public (D20): `git clone https://github.com/vincentl/pi-cluster pc && sudo bash pc/head/30-add-node.sh 1` | the 4.6 output | runs from a clone | 2 min |
