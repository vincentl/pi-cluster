# pi-cluster

Bash scripts and a guide for building a Raspberry Pi 5 HPC cluster: one head node booting
from NVMe, compute nodes network-booting a read-only NFS root served by the head node. Slurm
is the target scheduler. Sole maintainer: Vincent.

`Readme.md` is the specification. Scripts exist to make it true. When reality forces a change,
change the Readme in the same commit and say so.

## Target platform

- Raspberry Pi 5. Raspberry Pi OS Lite 64-bit, Debian 13 "trixie" (release 2026-09-15,
  kernel 6.18). Re-check https://www.raspberrypi.com/software/operating-systems/ before assuming.
- Workstation: macOS, Linux or Windows 10+, with Raspberry Pi Imager and an OpenSSH client.
  Nothing in this repo runs on the workstation.
- Cluster LAN: head node `10.0.0.1/8` on `eth0`; compute node N is `10.0.1.N`, hostname
  `<NODE_PREFIX>NNN`. All values live in `cluster.env`.

## Layout

- `cluster.env`: the only settings file. KEY=value, sourced by every script.
- `head/`: bash, run as root on the head node, in numeric order. `lib.sh` is sourced by the rest.
  `image-run.sh` runs a command inside the compute image with systemd-nspawn.
- `notes/`: working notes not yet turned into scripts.
- `docs/`: `images/` with its figure list, `testing.md` hardware checklist.
- `.github/workflows/`: `make check` on push. Remote `origin` is the private
  `github.com/vincentl/pi-cluster-dev` (D29). A public `vincentl/pi-cluster` comes near the end
  and gets only the public files: `Readme.md`, `LICENSE`, `cluster.env`, `head/`, the figures in
  `docs/images/`, `Makefile`, `.shellcheckrc`, `.github/`, `.gitignore`. Public files never link
  to the private ones (`ai/`, `notes/`, `docs/testing.md`, `CLAUDE.md`, `docs/images/README.md`).
- `ai/`: prompts, audits, decisions, plans and test logs for Claude sessions. Start at `ai/README.md`.

## Conventions

- Bash only on the Pi. No Python, no configuration-management tools.
- Every script: `#!/bin/bash`, `source "$(dirname "$0")/lib.sh"` (which sets
  `set -euo pipefail` and loads `cluster.env`), root check, then numbered stages.
- Idempotent: every stage is guarded by a real check of the system state, so a rerun after a
  reboot or a failure continues where it left off. Never guard with a marker file.
- One comment line per stage saying what it does. Log with `log` from `lib.sh` so the user can
  follow along.
- Files the scripts generate on the head node carry a "generated by pi-cluster" header.
  Anything the user or `30-add-node.sh` appends to lives in a separate include file.
- Commit at phase boundaries. Message body says what was verified on hardware, or
  "not hardware-tested".

## Verify

```bash
make check
```

`shellcheck` and `bash -n` over `head/*.sh`. Hardware steps are checked by
a human following `docs/testing.md`; results go in `ai/test-logs/`.

## Don't

- Don't run anything from `head/` on the workstation.
- Don't ssh into the cluster unless `ai/decisions.md` D9 says it is allowed.
- Don't assert Raspberry Pi bootloader, Imager, or Debian trixie behaviour from memory.
  Fetch the doc or package page and cite it in the plan file.
- Don't commit downloaded images or anything from `~/.ssh`.
- Don't push without Vincent's OK, and never force-push.
